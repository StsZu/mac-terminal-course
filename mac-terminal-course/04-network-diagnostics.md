# Урок 4 — Мережева діагностика

## Про тему

Перед SSH до MikroTik, деплоєм або роботою з API перевіряєте: чи є інтернет, IP, шлюз, DNS, чи відповідає хост. Цей урок — стандартний чекліст «мережа працює?».

**Головна мета — не вивчити всі команди, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії.**

---

## Сценарії

| Задача | Команди |
|--------|---------|
| IP Mac | `ipconfig getifaddr en0`, `ifconfig` |
| Default gateway | `route get default` |
| DNS | `dig`, `nslookup` |
| Доступ до сайту | `ping`, `curl` |
| Відкритий порт | `lsof -i`, `netstat` |
| Перед MikroTik | IP → gateway → ping роутера |

---

## Команди

### `ping`

| | |
|---|---|
| **Що робить** | Перевіряє доступність хоста (ICMP) |
| **Коли** | Швидка перевірка інтернету або роутера |
| **Приклад** | `ping -c 4 8.8.8.8` |
| **Результат** | `4 packets transmitted, 4 received, 0.0% packet loss` |
| **Помилки** | `Request timeout` — немає маршруту або хост блокує ping |
| **Ризик** | низький |

---

### `traceroute`

| | |
|---|---|
| **Що робить** | Показує маршрут пакетів до хоста |
| **Коли** | Де «обривається» з'єднання |
| **Приклад** | `traceroute google.com` |
| **Результат** | Список hop-ів з IP і затримками |
| **Помилки** | `* * *` — hop не відповідає (часто нормально) |
| **Ризик** | низький |

---

### `route get default`

| | |
|---|---|
| **Що робить** | Показує маршрут за замовчуванням (шлюз) |
| **Коли** | Дізнатись IP роутера перед SSH |
| **Приклад** | `route get default` |
| **Результат** | `gateway: 192.168.1.1` |
| **Помилки** | Немає gateway — немає мережі |
| **Ризик** | низький |

---

### `ifconfig`

| | |
|---|---|
| **Що робить** | Список мережевих інтерфейсів і їх IP |
| **Коли** | Детальна інформація про Wi-Fi, Ethernet |
| **Приклад** | `ifconfig en0` |
| **Результат** | `inet 192.168.1.105 netmask 0xffffff00` |
| **Помилки** | Багато виводу — фільтруйте інтерфейс |
| **Ризик** | низький |

---

### `ipconfig getifaddr en0`

| | |
|---|---|
| **Що робить** | Лише IP-адреса інтерфейса (Wi-Fi зазвичай `en0`) |
| **Коли** | Швидко «мій IP?» |
| **Приклад** | `ipconfig getifaddr en0` |
| **Результат** | `192.168.1.105` |
| **Помилки** | Порожній вивід — Wi-Fi вимкнено або інший інтерфейс (`en1`) |
| **Ризик** | низький |

---

### `networksetup -listallhardwareports`

| | |
|---|---|
| **Що робить** | Список мережевих портів Mac |
| **Коли** | Дізнатись ім'я Wi-Fi/Ethernet для інших команд |
| **Приклад** | `networksetup -listallhardwareports` |
| **Результат** | `Hardware Port: Wi-Fi` `Device: en0` |
| **Помилки** | — |
| **Ризик** | низький |

---

### `networksetup -getinfo Wi-Fi`

| | |
|---|---|
| **Що робить** | IP, маска, роутер для Wi-Fi |
| **Коли** | Альтернатива `ifconfig` у зручному вигляді |
| **Приклад** | `networksetup -getinfo Wi-Fi` |
| **Результат** | `IP address: 192.168.1.105` `Router: 192.168.1.1` |
| **Помилки** | Невірне ім'я порту — перевірте `-listallhardwareports` |
| **Ризик** | низький |

---

### `dig`

| | |
|---|---|
| **Що робить** | DNS-запит (детальний) |
| **Коли** | Перевірити резолв домену |
| **Приклад** | `dig google.com` |
| **Результат** | `ANSWER SECTION: google.com. 300 IN A 142.250.x.x` |
| **Помилки** | `SERVFAIL`, `NXDOMAIN` — проблема DNS |
| **Ризик** | низький |

---

### `nslookup`

| | |
|---|---|
| **Що робить** | Простіший DNS-запит |
| **Коли** | Швидка перевірка домену |
| **Приклад** | `nslookup github.com` |
| **Результат** | `Address: 140.82.x.x` |
| **Помилки** | `can't find` — DNS не резолвить |
| **Ризик** | низький |

---

### `curl`

| | |
|---|---|
| **Що робить** | HTTP-запит з Terminal |
| **Коли** | Перевірити, чи сайт/API відповідає |
| **Приклад** | `curl -I https://google.com` |
| **Результат** | `HTTP/2 200` + заголовки |
| **Помилки** | `Could not resolve host` — DNS; `Connection refused` — сервер недоступний |
| **Ризик** | низький (для `-I`); середній для `curl | bash` |

---

### `netstat`

| | |
|---|---|
| **Що робить** | Мережеві з'єднання і слухаючі порти |
| **Коли** | Що слухає на портах |
| **Приклад** | `netstat -an | grep LISTEN` |
| **Результат** | `tcp4  0  0  *.3000  *.*  LISTEN` |
| **Помилки** | Багато виводу — завжди фільтруйте `grep` |
| **Ризик** | низький |

---

### `lsof -i`

| | |
|---|---|
| **Що робить** | Який процес використовує мережевий порт |
| **Коли** | «Хто зайняв порт 3000?» |
| **Приклад** | `lsof -i :3000` |
| **Результат** | `node  12345 szubar  TCP *:3000 (LISTEN)` |
| **Помилки** | Порожній вивід — порт вільний |
| **Ризик** | низький |

---

## Чекліст перед роботою з MikroTik

```bash
ipconfig getifaddr en0          # 1. Є IP?
route get default               # 2. Є gateway?
ping -c 3 192.168.1.1           # 3. Роутер відповідає? (ваш gateway)
dig google.com                  # 4. DNS працює?
curl -I https://google.com      # 5. Інтернет є?
```

---

## Практичне завдання

1. Дізнайтесь свій IP: `ipconfig getifaddr en0`
2. Знайдіть gateway: `route get default` — запишіть IP роутера
3. `ping -c 4` до gateway і до `8.8.8.8`
4. `dig github.com` і `nslookup github.com` — порівняйте
5. `curl -I https://github.com` — який HTTP-код?
6. Запустіть локальний сервер (якщо є) або перевірте `lsof -i :22`
