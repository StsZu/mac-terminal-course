# Урок 5 — SSH та MikroTik

## Про тему

**SSH** (Secure Shell) — зашифроване підключення до віддаленої машини. На MikroTik через SSH ви керуєте роутером, переглядаєте конфіг, робите бекап. **SCP** — копіювання файлів через той самий канал.

**Головна мета — не вивчити всі команди, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії.**

---

## Перед SSH до MikroTik перевір

1. **Чи є IP на Mac** — `ipconfig getifaddr en0`
2. **Чи є default gateway** — `route get default`
3. **Чи пінгується роутер** — `ping -c 3 10.0.0.254` (ваш IP)
4. **Чи правильний username** — наприклад `Stas`, не `admin` якщо так налаштовано
5. **Чи дозволений SSH на MikroTik** — порт 22, сервіс увімкнено в Winbox/CLI

```bash
ipconfig getifaddr en0
route get default
ping -c 3 10.0.0.254
networksetup -getinfo Wi-Fi
```

## Команди

### `ssh`

| | |
|---|---|
| **Що робить** | Підключення до віддаленого хоста |
| **Коли** | Керування MikroTik, сервером, VPS |
| **Приклад** | `ssh Stas@10.0.0.254` |
| **Результат** | `[Stas@MikroTik] >` — інтерактивна сесія |
| **Помилки** | `Connection refused` — SSH вимкнено; `Permission denied` — пароль/ключ; `No route to host` — мережа |
| **Ризик** | середній (зміна конфігурації на віддаленій системі) |

Перше підключення:
```
The authenticity of host '10.0.0.254' can't be established.
Are you sure you want to continue connecting (yes/no)?
```
Введіть `yes` — це нормально для вашого роутера.

---

### `scp`

| | |
|---|---|
| **Що робить** | Secure Copy — копіювання файлів через SSH |
| **Коли** | Бекап конфігу MikroTik, завантаження файлів на сервер |
| **Приклад** | `scp backup.rsc Stas@10.0.0.254:` |
| **Результат** | Файл скопійовано в home-директорію на роутері |
| **Помилки** | Ті самі, що в SSH + `No such file` |
| **Ризик** | середній |

Напрямки:
```bash
# Mac → MikroTik
scp backup.rsc Stas@10.0.0.254:

# MikroTik → Mac
scp Stas@10.0.0.254:backup.rsc .

# З вказанням шляху
scp ./config/backup.rsc Stas@10.0.0.254:/flash/
```

---

### `ssh-keygen`

| | |
|---|---|
| **Що робить** | Генерує пару SSH-ключів (публічний + приватний) |
| **Коли** | Вхід без пароля; безпечніше за пароль у скриптах |
| **Приклад** | `ssh-keygen -t ed25519 -C "szubar@macbook"` |
| **Результат** | `~/.ssh/id_ed25519` (приватний) і `.pub` (публічний) |
| **Помилки** | Перезапис існуючого ключа — обережно |
| **Ризик** | низький (генерація); **високий** (витік приватного ключа) |

---

### `ssh-copy-id`

| | |
|---|---|
| **Що робить** | Копіює публічний ключ на віддалений сервер |
| **Коли** | Налаштувати вхід по ключу |
| **Приклад** | `ssh-copy-id Stas@10.0.0.254` |
| **Результат** | Ключ додано в `~/.ssh/authorized_keys` на сервері |
| **Помилки** | На Mac може не бути — тоді вручну: `cat ~/.ssh/id_ed25519.pub \| ssh Stas@10.0.0.254 'cat >> .ssh/authorized_keys'` |
| **Ризик** | середній |

---

### `ping` (повтор)

| | |
|---|---|
| **Що робить** | Перевірка доступності роутера |
| **Коли** | **Перед** SSH — обов'язковий крок |
| **Приклад** | `ping -c 3 10.0.0.254` |
| **Результат** | `0.0% packet loss` |
| **Помилки** | 100% loss — не підключайтесь по SSH, спочатку мережа |
| **Ризик** | низький |

---

### `route get default` (повтор)

| | |
|---|---|
| **Що робить** | Шлюз за замовчуванням |
| **Коли** | Переконатись, що Mac у тій самій підмережі, що MikroTik |
| **Приклад** | `route get default` |
| **Результат** | `gateway: 10.0.0.254` |
| **Помилки** | — |
| **Ризик** | низький |

---

### `networksetup -getinfo Wi-Fi` (повтор)

| | |
|---|---|
| **Що робить** | IP, маска, роутер Wi-Fi |
| **Коли** | Швидка діагностика перед SSH |
| **Приклад** | `networksetup -getinfo Wi-Fi` |
| **Результат** | IP і Router |
| **Помилки** | — |
| **Ризик** | низький |

## Типовий workflow MikroTik

```bash
# 1. Діагностика мережі
ipconfig getifaddr en0
route get default
ping -c 3 10.0.0.254

# 2. Підключення
ssh Stas@10.0.0.254

# 3. На роутері (приклад) — експорт конфігу
# /export file=backup

# 4. Вихід з SSH
# /quit  або  Ctrl+D

# 5. Завантажити бекап на Mac
scp Stas@10.0.0.254:backup.rsc .
```

---

## Практичне завдання

1. Виконайте pre-check (5 пунктів вище) — запишіть IP, gateway, результат ping.
2. Підключіться: `ssh Stas@10.0.0.254` (або ваш роутер). Вийдіть через `exit`.
3. Згенеруйте ключ: `ssh-keygen -t ed25519` (passphrase за бажанням).
4. Подивіться публічний ключ: `cat ~/.ssh/id_ed25519.pub`
5. Симулюйте SCP: `scp --help` або скопіюйте тестовий файл, якщо є доступ до роутера.
