# Урок 6 — Git та GitHub

## Про тему

**Git** — система контролю версій локально. **GitHub** — хмарне сховище репозиторіїв. **`gh`** — офіційний CLI для GitHub (авторизація, перегляд репо).

Щоденний цикл: `status` → `diff` → `add` → `commit` → `push`. Перед pull — переконайтесь, що немає незакомічених змін або зробіть stash.

**Головна мета — не вивчити всі команди, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії.**

---

## Команди

### `git status`

| | |
|---|---|
| **Що робить** | Стан робочої директорії і staging |
| **Коли** | **Перша команда** перед будь-якими діями |
| **Приклад** | `git status` |
| **Результат** | `On branch main` `Changes not staged for commit:` |
| **Помилки** | `not a git repository` — не в папці з `.git` |
| **Ризик** | низький |

---

### `git add .`

| | |
|---|---|
| **Що робить** | Додає зміни в staging (підготовка до commit) |
| **Коли** | Після перевірки `status` і `diff` |
| **Приклад** | `git add .` або `git add src/app.js` |
| **Результат** | `Changes to be committed:` |
| **Помилки** | Додали зайве — `git restore --staged файл` |
| **Ризик** | низький |

---

### `git commit -m "message"`

| | |
|---|---|
| **Що робить** | Фіксує зміни з повідомленням |
| **Коли** | Логічно завершений шматок роботи |
| **Приклад** | `git commit -m "Add login form"` |
| **Результат** | `[main abc1234] Add login form` `1 file changed` |
| **Помилки** | `nothing to commit` — спочатку `git add` |
| **Ризик** | низький |

---

### `git push`

| | |
|---|---|
| **Що робить** | Відправляє коміти на віддалений репозиторій |
| **Коли** | Після локальних commit-ів |
| **Приклад** | `git push` або `git push origin main` |
| **Результат** | `main -> main` |
| **Помилки** | `rejected` — спочатку `git pull`; `auth failed` — перевірте SSH/токен |
| **Ризик** | середній (публікація змін для команди) |

---

### `git pull`

| | |
|---|---|
| **Що робить** | Завантажує і зливає зміни з remote |
| **Коли** | Перед початком роботи; коли push відхилено |
| **Приклад** | `git pull` |
| **Результат** | `Already up to date` або `Fast-forward` |
| **Помилки** | Merge conflicts — треба вирішити вручну |
| **Ризик** | середній |

---

### `git log --oneline`

| | |
|---|---|
| **Що робить** | Коротка історія комітів |
| **Коли** | Подивитись, що було зроблено |
| **Приклад** | `git log --oneline -10` |
| **Результат** | `abc1234 Add login form` |
| **Помилки** | — |
| **Ризик** | низький |

---

### `git branch`

| | |
|---|---|
| **Що робить** | Список гілок; `git branch feature` — створити |
| **Коли** | Паралельна розробка фіч |
| **Приклад** | `git branch` |
| **Результат** | `* main` `  feature-login` |
| **Помилки** | — |
| **Ризик** | низький |

---

### `git checkout`

| | |
|---|---|
| **Що робить** | Перемикання гілки або файлу (legacy) |
| **Коли** | Перейти на іншу гілку |
| **Приклад** | `git checkout feature-login` |
| **Результат** | `Switched to branch 'feature-login'` |
| **Помилки** | Uncommitted changes — commit або stash |
| **Ризик** | середній |

---

### `git switch`

| | |
|---|---|
| **Що робить** | Сучасна заміна checkout для гілок |
| **Коли** | Перемикання гілок (рекомендовано) |
| **Приклад** | `git switch main` |
| **Результат** | `Switched to branch 'main'` |
| **Помилки** | Ті самі, що в checkout |
| **Ризик** | середній |

---

### `git diff`

| | |
|---|---|
| **Що робить** | Показує різницю між версіями |
| **Коли** | **Перед commit** — що саме змінилось |
| **Приклад** | `git diff` (незастейджені) / `git diff --staged` |
| **Результат** | `+ новий рядок` `- видалений рядок` |
| **Помилки** | — |
| **Ризик** | низький |

---

### `git restore`

| | |
|---|---|
| **Що робить** | Скасовує зміни у файлі |
| **Коли** | Випадково змінили файл — повернути |
| **Приклад** | `git restore app.js` |
| **Результат** | Файл як у останньому commit |
| **Помилки** | Незбережені зміни **втрачаються** |
| **Ризик** | середній |

---

### `gh auth status`

| | |
|---|---|
| **Що робить** | Статус авторизації GitHub CLI |
| **Коли** | Проблеми з push/pull через gh |
| **Приклад** | `gh auth status` |
| **Результат** | `✓ Logged in to github.com as username` |
| **Помилки** | `not logged in` — `gh auth login` |
| **Ризик** | низький |

---

### `gh repo view`

| | |
|---|---|
| **Що робить** | Інформація про репозиторій |
| **Коли** | Швидкий огляд без браузера |
| **Приклад** | `gh repo view` |
| **Результат** | Назва, опис, URL, статистика |
| **Помилки** | Не в git-репо або не на GitHub |
| **Ризик** | низький |

---

## Сценарії

### Перевірити стан проєкту
```bash
cd ~/Projects/my-project
git status
git log --oneline -5
```

### Зробити commit і push
```bash
git status
git diff
git add .
git commit -m "Fix header layout"
git push
```

### Подивитись diff перед commit
```bash
git diff
git diff --staged   # після git add
```

### Підтягнути зміни з GitHub
```bash
git status          # чисто?
git pull
```

---

## Практичне завдання

1. `cd` у будь-який git-проєкт. `git status`, `git log --oneline -5`
2. Змініть файл. `git diff` → `git add .` → `git diff --staged`
3. `git commit -m "Practice: terminal course"` (не push, якщо не хочете публікувати)
4. `git branch` — на якій гілці ви?
5. `gh auth status` і `gh repo view` (якщо `gh` встановлено)
