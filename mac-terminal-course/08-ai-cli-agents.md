# Урок 8 — AI CLI агенти

## Про тему

На вашому Mac доступні CLI-агенти: **`claude`**, **`codex`**, **`gemini`**, **`grok`**. Вони працюють у Terminal і можуть редагувати файли, запускати команди, аналізувати проєкт.

**Критично:** агент змінює файли на диску. Завжди працюйте в папці проєкту з чистим `git status` або свіжим commit — інакше втратите зміни або отримаєте хаос.

**Головна мета — не вивчити всі команди, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії.**

## Перевірка встановлення

### `which claude` / `which codex` / `which gemini` / `which grok`

| | |
|---|---|
| **Що робить** | Шлях до виконуваного файлу агента |
| **Коли** | Перед першим запуском |
| **Приклад** | `which claude` |
| **Результат** | `/usr/local/bin/claude` або `/opt/homebrew/bin/claude` |
| **Помилки** | `claude not found` — не встановлено або не в PATH |
| **Ризик** | низький |

### `command -v claude` (і аналоги)

| | |
|---|---|
| **Що робить** | POSIX-перевірка наявності (краще для скриптів) |
| **Коли** | Автоматизація, надійна перевірка |
| **Приклад** | `command -v codex` |
| **Результат** | Шлях або порожньо + exit 1 |
| **Помилки** | — |
| **Ризик** | низький |

Швидка перевірка всіх:
```bash
for cmd in claude codex gemini grok; do
  echo -n "$cmd: "
  command -v "$cmd" || echo "NOT FOUND"
done
```

## Чому `git status` перед агентом

1. **Бачите baseline** — що змінилось після сесії (`git diff`)
2. **Можете відкотити** — `git restore .` або `git checkout .`
3. **Можете закомітити** — зберегти хороші зміни агента
4. **Уникаєте конфліктів** — агент + ваші незакомічені зміни = плутанина

### Чому небезпечно без backup / commit

- Агент може видалити файли (`rm`), перезаписати конфіги
- Немає «Undo» як у редакторі — лише Git або Time Machine
- Агент може запустити `npm install`, змінити `package.json`, поламати збірку

## Рекомендований workflow

```bash
cd ~/Projects/project-name
git status                    # має бути чисто або свідомі зміни
git pull                      # актуальна версія
git checkout -b ai-experiment # окрема гілка (рекомендовано)

# перевірка агента
which claude
command -v claude

# запуск
claude
# або
codex
# або
gemini
# або
grok

# після сесії
git status
git diff
git add .
git commit -m "AI: describe changes"
```

### Мінімальний безпечний варіант

```bash
cd ~/Projects/project-name
git status
git stash                     # сховати свої зміни
claude
git stash pop                 # повернути свої зміни
```

## Правила роботи з AI CLI

| Правило | Чому |
|---------|------|
| Завжди `git status` | Контроль змін |
| Окрема гілка для експериментів | Легкий відкат |
| Не запускати в `/` або `~` без потреби | Агент може чіпати зайве |
| Читати, що агент **збирається** виконати | Особливо `rm`, `curl \| bash` |
| Commit після успішної сесії | Зберегти результат |

## Практичне завдання

1. Перевірте всі агенти: `which claude codex gemini grok`
2. `command -v` для кожного — порівняйте з `which`
3. `cd` у тестовий проєкт. `git status` — що показує?
4. Створіть гілку: `git switch -c terminal-ai-practice`
5. **Не запускайте агент**, якщо не готові — замість цього опишіть workflow у 5 кроків своїми словами
