# Урок 9 — Небезпечні команди

## Про тему

Деякі команди потужні і **незворотні**. Помилка в одному аргументі може знищити дані, зламати мережу або виконати шкідливий скрипт з інтернету.

Правило інженера: **спочатку зрозуміти → перевірити шлях → зробити backup → виконати**.

**Головна мета — не вивчити всі команди, а навчитися швидко знаходити потрібну команду, розуміти її ризик і застосовувати її в реальному сценарії.**

---

## Команди

### `sudo`

| | |
|---|---|
| **Чому небезпечна** | Виконує команду як root — повний доступ до системи |
| **Коли використовується** | Системні зміни: встановлення в `/usr`, мережеві налаштування |
| **Як перевірити** | Чи дійсно потрібні root-права? Спробуйте без `sudo` |
| **Безпечніша альтернатива** | `brew install` замість ручного копіювання в системні папки |
| **Ризик** | **високий** |

---

### `rm -rf`

| | |
|---|---|
| **Чому небезпечна** | Видаляє без підтвердження; помилка в шляху = втрата даних |
| **Коли використовується** | Очистка `node_modules`, тимчасових build-папок |
| **Як перевірити** | `pwd` + `ls` + `echo` шляху; використайте `rm -r` без `-f` спочатку |
| **Безпечніша альтернатива** | Перемістити в кошик: `mv folder ~/.Trash/`; `trash` (brew) |
| **Ризик** | **високий** |

**Ніколи:** `rm -rf /`, `rm -rf ~`, `rm -rf /*`

---

### `diskutil`

| | |
|---|---|
| **Чому небезпечна** | Керує дисками: форматування, стирання, розділи |
| **Коли використовується** | Підготовка USB, перевірка дисків |
| **Як перевірити** | `diskutil list` — переконайтесь у **правильному** диску |
| **Безпечніша альтернатива** | Для перегляду: `diskutil list`; форматування — через Disk Utility GUI |
| **Ризик** | **високий** (для `eraseDisk`, `partitionDisk`) |

---

### `chmod -R`

| | |
|---|---|
| **Чому небезпечна** | Рекурсивно змінює права; `chmod -R 777` відкриває все всім |
| **Коли використовується** | Виправити права на скрипт або папку проєкту |
| **Як перевірити** | `ls -la` до і після; мінімальні права: `chmod +x script.sh` |
| **Безпечніша альтернатива** | `chmod 755 file` без `-R`; лише конкретний файл |
| **Ризик** | **високий** (з `-R` на `/` або `~`) |

---

### `chown -R`

| | |
|---|---|
| **Чому небезпечна** | Змінює власника файлів рекурсивно |
| **Коли використовується** | Виправлення прав після `sudo` операцій |
| **Як перевірити** | `ls -la` — хто зараз власник? |
| **Безпечніша альтернатива** | `chown user:group single-file` без `-R` |
| **Ризик** | **високий** |

---

### `kill`

| | |
|---|---|
| **Чому небезпечна** | Примусово завершує процес за PID |
| **Коли використовується** | Завислий сервер, процес на порту |
| **Як перевірити** | `ps aux | grep name` або `lsof -i :PORT` — правильний PID? |
| **Безпечніша альтернатива** | `kill PID` (SIGTERM) перед `kill -9 PID` |
| **Ризик** | середній |

---

### `killall`

| | |
|---|---|
| **Чому небезпечна** | Завершує **всі** процеси з іменем |
| **Коли використовується** | `killall node`, `killall python3` |
| **Як перевірити** | `pgrep -l node` — скільки процесів? |
| **Безпечніша альтернатива** | `kill` конкретного PID |
| **Ризик** | **високий** (`killall Dock`, `killall Finder`) |

---

### `launchctl`

| | |
|---|---|
| **Чому небезпечна** | Керує системними сервісами macOS (boot, unload) |
| **Коли використовується** | Вимкнути/увімкнути user agent, діагностика |
| **Як перевірити** | `launchctl list | grep name` — що саме зупиняєте? |
| **Безпечніша альтернатива** | System Settings для сервісів; не чіпати `system/` plist без досвіду |
| **Ризик** | **високий** |

---

### `pfctl`

| | |
|---|---|
| **Чому небезпечна** | Керує firewall (packet filter) macOS |
| **Коли використовується** | Діагностика мережевих правил |
| **Як перевірити** | `sudo pfctl -s info` — лише читання |
| **Безпечніша альтернатива** | System Settings → Network → Firewall |
| **Ризик** | **високий** (при завантаженні правил) |

---

### `dd`

| | |
|---|---|
| **Чому небезпечна** | Побайтове копіювання; помилка `of=` = знищення диска |
| **Коли використовується** | Запис ISO на USB, forensic копії |
| **Як перевірити** | `diskutil list` — **тричі** перевірте `of=/dev/rdiskN` |
| **Безпечніша альтернатива** | Balena Etcher GUI |
| **Ризик** | **високий** |

---

### `mv`

| | |
|---|---|
| **Чому небезпечна** | Перезаписує файл призначення **без попередження** |
| **Коли використовується** | Перейменування, переміщення |
| **Як перевірити** | `ls` у папці призначення; `mv -i` для інтерактивного режиму |
| **Безпечніша альтернатива** | `cp` + перевірка + `rm` |
| **Ризик** | середній |

---

### `scp`

| | |
|---|---|
| **Чому небезпечна** | Копіює файли на віддалений сервер; можна перезаписати production |
| **Коли використовується** | Деплой, бекапи MikroTik |
| **Як перевірити** | Правильний `user@host` і шлях? `ssh` спочатку для перевірки |
| **Безпечніша альтернатива** | `scp` у staging; Git deploy замість ручного scp |
| **Ризик** | середній |

---

### `curl | bash`

| | |
|---|---|
| **Чому небезпечна** | Завантажує скрипт з інтернету і **одразу виконує** |
| **Коли використовується** | Інсталятори: Homebrew, nvm, rustup |
| **Як перевірити** | Спочатку `curl -fsSL URL -o install.sh`, прочитати `less install.sh`, потім `bash install.sh` |
| **Безпечніша альтернатива** | Офіційний `.pkg`, `brew install`, перевірка checksum |
| **Ризик** | **високий** |

#### Приклад з інсталятора Homebrew

```bash
# Небезпечно без розуміння:
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Безпечніший підхід:
curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh -o brew-install.sh
less brew-install.sh    # прочитати
bash brew-install.sh    # виконати свідомо
```

Якщо URL скомпрометовано або підмінено — `curl | bash` виконає шкідливий код з правами вашого користувача.

## Матриця ризиків

| Команда | Ризик | Головна загроза |
|---------|-------|-----------------|
| `sudo` | високий | Системні зміни |
| `rm -rf` | високий | Втрата даних |
| `diskutil eraseDisk` | високий | Стирання диска |
| `chmod -R 777` | високий | Відкритий доступ |
| `chown -R` | високий | Зламані права |
| `kill` / `killall` | середній–високий | Зупинка процесів |
| `launchctl unload` | високий | Зламані сервіси |
| `pfctl -f` | високий | Мережеві правила |
| `dd` | високий | Знищення диска |
| `mv` | середній | Перезапис файлів |
| `scp` | середній | Перезапис на сервері |
| `curl \| bash` | високий | Виконання невідомого коду |

## Практичне завдання

1. Для кожної команди з уроку запишіть: **що перевірити перед запуском**.
2. Порівняйте: `rm -r test-dir` vs `rm -rf test-dir` на тестовій папці.
3. Завантажте скрипт без виконання: `curl -fsSL URL -o script.sh` (будь-який публічний raw-файл).
4. `diskutil list` — **лише читання**. Знайдіть свій системний диск.
5. `launchctl list | head -10` — що запущено?

## Міні-чекліст

- [ ] Перед `rm -rf` завжди `pwd` і `ls`
- [ ] Не використовую `curl | bash` без читання скрипта
- [ ] Розумію, що `sudo` = root-права
- [ ] `kill` лише після перевірки PID
- [ ] `diskutil` і `dd` — лише з впевненістю в диску
- [ ] Знаю безпечніші альтернативи для кожної небезпечної команди
